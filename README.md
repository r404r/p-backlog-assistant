# backlog-assistant

日本語 | [English](README.en.md)

Nulab [Backlog](https://backlog.com/ja/) の課題とユーザ情報を、ローカルにキャッシュしながら安全に抽出・一括更新するデスクトップアプリです。MIT License のオープンソースソフトウェアです。

- 技術スタック: [Wails v2](https://wails.io/) + Vue 3 + TypeScript / Go
- ローカルキャッシュ: SQLite([modernc.org/sqlite](https://pkg.go.dev/modernc.org/sqlite)、純 Go)
- Excel 入出力: [excelize](https://github.com/qax-os/excelize)
- 配布対象: Windows / macOS(GitHub Actions で自動ビルド)

## ダウンロード

[Releases](https://github.com/r404r/p-backlog-assistant/releases) から最新版の zip(Windows / macOS)をダウンロードして展開してください。開発中の最新ビルドは Actions の Artifacts にあります。

インストール手順・各画面の操作方法・Excel テンプレートの記入規則は [ユーザガイド](docs/USER_GUIDE.md) を参照してください。

## 機能

### 接続設定
- 複数スペースのプロファイル管理(登録・変更・削除・切替)。保存前に接続テスト必須
- **API キーは OS キーチェーン**(Windows 資格情報マネージャー / macOS Keychain)にのみ保存
- 権限状態の実測表示(管理者機能が使えない場合は縮退内容を明示)

### 課題抽出
- 課題の同期: 自動(初回フル)/ フル / 差分。差分は `updatedSince` + activities による削除検知で API 呼び出しを節約
- 同期中は取得件数の進捗を表示。同期中は全画面でプロジェクト切替・検索・Excel 出力・一括更新を抑止(途中状態のローカル DB を読ませないため)
- ローカル DB 検索: キーワード(課題キー + 件名 + 詳細。スペース区切りの複数語を AND / OR で切替。入力欄で Enter 実行)・作成/更新日範囲・状態・担当者
- 検索結果は **200 件ごとのページ表示**(最初 / 前へ / ページ番号入力 / 次へ / 最後)。総件数と表示範囲(x〜y 件目)を明示し、同期や課題の最新取得でデータが変わった場合はページャを無効にして再検索を案内
- **カスタム属性**での絞り込み・一覧表示・出力(テキストは部分一致、数値・日付は範囲、リスト系は選択肢の複数選択)
- 検索結果一覧の**課題キーをクリックすると課題詳細をポップアップ表示**(カスタム属性・親課題・詳細本文まで確認可能。URL のコピー・ブラウザで開くもここから可能)。**隣のクリップボードアイコンで課題 URL を直接コピー**
- 詳細ポップアップの**「最新の状態を取得」**で、その課題 1 件だけを Backlog から取得し直してローカルへ反映(プロジェクト全体の同期は不要)。あわせて**コメント(最新 500 件まで)も取得・表示**(コメントは通常の同期では取得されず、キーワード検索・Excel 出力の対象外)
- **Excel 出力**(列選択、条件一致を最大 100 万件まで。超過時は出力せずエラー)。カスタム属性列・親課題キー列も選択可

### 一括更新・追加
- テンプレート Excel 出力(既存課題 + 競合検知用 `base_updated`、プロジェクト ID 埋め込みで誤書き込み防止)。**検索条件(キーワード AND / OR・作成/更新日範囲・状態・担当者)で対象を絞って出力**できます(条件なしなら全件)
- **名前で編集**: 種別・状態・優先度・担当者は「マスタ」シート参照のドロップダウンから選択(担当者は同名対策で「表示名 (ID)」形式)
- 取り込み検証(名前列が常に正・名前列が空の行のみ ID 列・食い違う ID 列は警告して無視・新規行の必須チェック)→ **dry-run プレビュー必須** → 確認つき実行
- 実行直前の競合検知(リモートが更新済みなら書き込まない。上書きは明示的な force のみ)
- **二重作成防止**: 送信状態を永続化し、成否不明(5xx・応答欠落等)は保留。再開時は作成済み課題との突合で安全に再送
- 進捗表示・キャンセル・ジョブ履歴(行明細)・結果レポート Excel。**新規追加が成功した行には作成された課題のキー・ID を記録**(結果レポートでキー・ID、行明細でキーを確認可)
- **カスタム属性・親課題キーの更新**にも対応(カスタム属性は「属性:定義名」列、親課題は 1 階層まで)
- レート制限(update 区分)の自動スロットリング + 一括実行中の API 呼び出しは最低 1 秒間隔(書き込み・競合確認・再送前の突合とも対象)

### ユーザ抽出
- ユーザ一覧 + 所属チーム・ロール・参加プロジェクト・管理者プロジェクトを抽出し Excel 出力
- 絞り込み: キーワード(名前・ユーザ ID・メールアドレスの部分一致)・ロール(スペース全体の権限)
- 管理者権限が無い場合は**参加プロジェクト単位の取得へ自動縮退**(取得できる範囲を明示)

### 同期状態・動作ログ
- データ種別ごとの最終同期時刻の一覧と手動同期
- レート制限の残量表示(区分ごとの残量 / 上限・リセット時刻。10 秒ごとに自動更新。サーバ応答から観測した実測値のため、表示の更新で API は消費しません)
- 動作ログを **実行ファイルと同じフォルダの `logs/`** に日付別で出力(14 日保持)。14 日を過ぎたログは起動時にバックグラウンドで gzip 圧縮して `logs/archive/` へ移動し、**アーカイブは 90 日保持**します。API キー・課題内容・ユーザ名は記録せず、URL のスペース名やホームフォルダ名はマスクされます(不具合調査時の共有を想定した設計ですが、共有前に内容の確認を推奨します)

### アプリ情報
- バージョン・作者・リポジトリ(不具合報告先)・ドキュメント(README / ユーザガイド)・連絡先・ライセンスの表示
- 保存データの所在: 設定フォルダ、プロファイルごとのローカル DB(パスとサイズ)、動作ログ
- **表示テーマ**の切り替え: システムに合わせる(既定)/ ライト / **ダーク**。選択は即時反映され次回起動時も維持(タイトルバーは Windows のみ追従。macOS は OS の外観設定に従う)
- **言語 / Language** の切り替え: システムに合わせる(既定)/ 日本語 / English。選択は即時反映され次回起動時も維持(「システムに合わせる」は OS・ブラウザ(実行環境)の言語設定に追従します)
  - **現時点の制限**: バックエンド(Go)が生成する一部のメッセージ(検証エラーや処理結果の詳細文)と、Excel 出力・一括更新テンプレートの見出し・記入方法シートは現時点では日本語のみです

## データの保存場所

| データ | 場所 |
|---|---|
| 設定(プロファイル。キーは含まない) | `ユーザ設定ディレクトリ/backlog-assistant/config.json`(Windows: `%AppData%\backlog-assistant\config.json`、通常は `C:\Users\<ユーザ名>\AppData\Roaming\backlog-assistant\config.json`) |
| API キー | OS キーチェーンのみ |
| ローカル DB(取得データ・SQLite) | 同上 `data\<スペースホスト>_<ユーザID>.db`(Windows: `%AppData%\backlog-assistant\data\`、通常は `C:\Users\<ユーザ名>\AppData\Roaming\backlog-assistant\data\`。Unix 系では権限 0600、Windows はユーザディレクトリの ACL に従う) |
| 動作ログ | EXE と同じフォルダの `logs\`(書込不可の場合はユーザ設定ディレクトリへ自動フォールバック) |

### 保存先の変更

設定とローカル DB の置き場所(**基点フォルダ**)は、次の 2 つの方法で変更できます。API キー(OS キーチェーン)と動作ログ(EXE と同じフォルダの `logs\`。書込不可の場合はユーザ設定ディレクトリへ自動フォールバック)の場所は変わりません。

| 方法 | 設定 | 基点フォルダ |
|---|---|---|
| ポータブル | EXE と同じフォルダに `portable.txt` を置く(内容は空でよい)。**macOS は `.app` バンドルと同じ階層**(バンドルの中ではない)に置く | `portable.txt` と同じフォルダの `userdata\`(macOS は `.app` バンドルと同じ階層の `userdata/`) |
| 環境変数 | `BACKLOG_ASSISTANT_HOME` にフォルダを指定する | 指定したフォルダ |

- **優先順位は ポータブル > 環境変数 > 既定** です(両方を指定した場合はポータブルが使われます)。
- 環境変数は**絶対パスのみ**です。`~` や `%AppData%` は展開されず、`?` を含むパスも使えません。
- 指定した保存先が使えない場合(USB ドライブの取り外し・書込不可など)は、**既定の場所へ勝手に切り替えず起動を中止します**。黙って既定へ移ると別の場所に空のデータが作られ、「データが消えた」ように見えるためです。理由は動作ログ、または EXE と同じフォルダ(書き込めない場合はユーザ設定ディレクトリ)の `crash.txt` に記録されます(記録先はカスタマイズの影響を受けません)。
- 保存先を切り替えても**データは自動で移動しません**。引き継ぐ場合はアプリを終了してから基点フォルダごとコピーしてください(手順は[ユーザガイドの「5.4 保存先の変更」](docs/USER_GUIDE.md#54-保存先の変更))。
- 現在の保存先は「アプリ情報」画面の「保存データ」で確認できます(保存先モードと実際のパス)。

### 移行の例: 環境変数モードからポータブルモードへ

同じパソコンで、環境変数(`BACKLOG_ASSISTANT_HOME`)で指定していた保存先を、USB メモリなどで持ち運べるポータブル運用へ切り替える手順です。**基点フォルダの直下に `config.json`、その下の `data\` にローカル DB** という構成は、どちらのモードでも同じです。

1. **アプリを終了します。** 起動中にコピーするとローカル DB が壊れることがあります。
2. 実行ファイル(EXE)と同じフォルダに、空の **`portable.txt`** を作成します。**macOS は `Backlog Assistant.app` の中ではなく、バンドルと同じ階層**に置きます。
3. その隣に **`userdata`** フォルダを作成します。
4. 旧基点フォルダから、**`config.json` を `userdata\` の直下へ**、**`data` フォルダを `userdata\data\` へ**コピーします(`.db-wal` `.db-shm` が残っている場合は一緒にコピーします)。
5. アプリを起動し、「アプリ情報」画面の「保存データ」で**「保存先モード」が「ポータブル(portable.txt)」**になっていること、「設定フォルダ」「ローカル DB」のパスが `userdata` 配下を指していることを確認します。

**同じパソコン・同じユーザアカウントであれば、API キーの再入力は不要です**(API キーは OS のキーチェーンに保存されており、保存先とは無関係です)。

**移行前(環境変数モード)の配置例**

```
D:\ba-data\                            ← BACKLOG_ASSISTANT_HOME に指定した基点フォルダ
├─ config.json                         ← 設定(プロファイル。キーは含まない)
└─ data\                               ← ローカル DB
   ├─ example.backlog.jp_12345.db
   ├─ example.backlog.jp_12345.db-wal
   └─ example.backlog.jp_12345.db-shm
```

**移行後(ポータブルモード)の配置例**

```
E:\BacklogAssistant\                   ← USB メモリなど、実行ファイルを置いたフォルダ
├─ backlog-assistant.exe
├─ portable.txt                        ← これがあるとポータブルモード(内容は空でよい)
├─ logs\                               ← 動作ログ(移行不要。書込不可の場合はユーザ設定ディレクトリへ)
└─ userdata\                           ← 基点フォルダ
   ├─ config.json                      ← 基点フォルダの直下
   └─ data\                            ← 基点フォルダの data\ 配下
      ├─ example.backlog.jp_12345.db
      ├─ example.backlog.jp_12345.db-wal
      └─ example.backlog.jp_12345.db-shm
```

- **切り替え後は環境変数 `BACKLOG_ASSISTANT_HOME` を削除することを推奨します。** 優先順位は ポータブル > 環境変数 のため残っていても動作しますが、`portable.txt` を外したときに古い保存先へ戻るため、混乱の元になります。
- **元のフォルダは移動ではなくコピーで残し、動作確認が済んでから削除してください。**
- **`Program Files` 配下など書き込めない場所に置くと起動時にエラーになります**(既定の場所へは勝手に切り替わりません)。USB メモリやユーザフォルダ配下に置いてください。
- **別のパソコンへ移す場合は API キーの再入力が必要です**(手順は[ユーザガイドの「5.5 別のパソコンへの移行」](docs/USER_GUIDE.md#55-別のパソコンへの移行))。
- 注意事項の詳細(クラウド同期フォルダの非推奨など)は[ユーザガイドの「5.4 保存先の変更」](docs/USER_GUIDE.md#54-保存先の変更)を参照してください。

## セキュリティ方針

- 接続先は HTTPS の `*.backlog.jp` / `*.backlog.com` のみ許可し、リダイレクト追従は無効
- レート制限は初回 API 利用時に `GET /api/v2/rateLimit` の実値から構成(ハードコードしない。取得失敗時は操作を継続し、30 秒以上経過後の次回 API 利用時に再試行)
- 設定・ローカル DB はユーザ領域に保存(Excel の出力先とログの場所は利用者の選択・配置に従う)

## 利用上の注意

- **一括更新・追加は Backlog のデータを変更します。** はじめてお使いの際は、参加者を自分だけにしたテスト用プロジェクトでの試行を推奨します
- ユーザ一覧・チームの全件取得には管理者(またはプロジェクト管理者)権限の API キーが必要です(無い場合は自動縮退)
- `#CLEAR#`(担当者・期限・詳細・カスタム属性・親課題のクリア)は公式 API 仕様に明記が無いため実機検証中の機能です

## 開発

必要環境: Go 1.25+ / Node.js 20.19+(または 22.13+ / 24+)/ Wails CLI v2.13

```sh
# テスト(全パッケージ)
go test ./...

# フロントエンドの lint・テスト・型検査・ビルド
cd frontend && npm install
npm run lint
npm run test
npm run build

# 開発モード(要 GUI 環境)
wails dev

# 配布ビルド
wails build
```

配布物は GitHub Actions(main への push)で Windows exe / macOS .app(zip)を自動ビルドし、Artifacts に保存します。macOS ビルドは macOS ランナーで行います。
