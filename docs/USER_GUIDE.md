## 1. はじめに

### このアプリでできること

Backlog の課題・ユーザ情報を **ローカルの SQLite データベースにキャッシュ**し、そのキャッシュに対して検索・絞り込み・Excel 出力を行います。Backlog へ書き込むのは「一括更新・追加」画面だけで、検索や Excel 出力では Backlog のデータは一切変更されません。

主な用途は次の 3 つです。

| やりたいこと | 使う画面 |
|---|---|
| 課題を条件で絞り込んで Excel に出したい | 課題抽出 |
| Excel で編集した内容を課題へまとめて反映したい / 課題をまとめて追加したい | 一括更新・追加 |
| ユーザ・チーム・プロジェクト参加状況を Excel に出したい | ユーザ抽出 |

### 動作環境

- Windows 10 / 11(x64)または macOS(Universal)
- Backlog の API キー(ユーザ抽出の全件取得には管理者またはプロジェクト管理者権限が必要です)
- 接続先は HTTPS の `*.backlog.jp` / `*.backlog.com` のみ利用できます

### インストール

1. [Releases](https://github.com/r404r/p-backlog-assistant/releases) から、お使いの OS 向けの zip をダウンロードします。
2. zip を展開します。
3. `backlog-assistant.exe`(Windows)または `Backlog Assistant.app`(macOS)を起動します。

**注意: 現時点では Windows / macOS とも配布バイナリはコード署名されていません。** 必ず上記の公式 Releases からダウンロードしたものだけをご利用ください。

- **Windows**: 初回起動時に SmartScreen の警告が出る場合があります。「詳細情報」→「実行」で起動できます。
- **macOS**: 署名・公証未対応のため、初回起動時に Gatekeeper にブロックされます。一度開こうとした後、「システム設定 → プライバシーとセキュリティ」下部の「このまま開く」を選択してください。

### 画面構成

左側のサイドバーで 6 つの画面を切り替えます。左上の `≡` ボタンでサイドバーを折りたたむことができ、折りたたみ状態は次回起動時にも引き継がれます。サイドバーの最下部には現在のバージョンが表示されます(折りたたみ中は表示されません)。

サイドバーの右端をマウスでドラッグすると幅を 140〜360px の範囲で調整できます。120px より狭くすると折りたたみ状態になり、折りたたみ中に右へドラッグすると展開します。右端をダブルクリックすると既定の幅(200px)に戻ります。調整した幅も次回起動時に引き継がれます。

| メニュー | 内容 |
|---|---|
| 接続設定 | 接続プロファイルの登録・変更・削除・切替 |
| 課題抽出 | 課題の同期・検索・Excel 出力 |
| 一括更新・追加 | テンプレート出力・取り込み・一括書き込み |
| ユーザ抽出 | ユーザの同期・絞り込み・Excel 出力 |
| 同期状態 | 最終同期時刻の一覧・手動同期・レート制限の残量 |
| アプリ情報 | バージョン・保存データの場所・動作ログ |

## 2. 初期設定(接続設定)

### 2.1 Backlog API キーの取得

1. ブラウザで Backlog にログインします。
2. 画面右上のユーザアイコンから「個人設定」を開きます。
3. 左メニューの「API」を開きます。
4. メモ(用途がわかる名前)を入力して登録すると、API キーが発行されます。
5. 発行された API キーをコピーします。

API キーは Backlog 上でも再表示できる場合がありますが、**本アプリに保存した API キーは再表示できません**。取り扱いには十分ご注意ください。

### 2.2 プロファイルの作成

初回起動時は「接続設定」画面に「ようこそ」というメッセージが表示されます。

1. 「プロファイルを登録する」ボタンを押します(2 件目以降はプロファイル一覧の下の「新規登録」ボタンです)。
2. **プロファイル名** に、判別しやすい名前を入力します(例: 開発チーム用)。
3. **スペース URL** に、`https://example.backlog.jp` の形式で入力します。
   - `https://` で始まる `*.backlog.jp` / `*.backlog.com` の URL のみ使用できます。
   - ポート番号・パス・クエリを含む URL は登録できません。
4. **API キー** に、2.1 でコピーしたキーを貼り付けます。
5. 「接続テスト」を押します。
6. 「接続テスト成功」と表示され、ユーザ名と権限状態(暫定)が出たら「保存」を押します。

> **ヒント**: 「接続テスト」が成功するまで「保存」ボタンは押せません。スペース URL または API キーを編集すると接続テストの結果は無効になり、再テストが必要になります。

保存が完了すると、実際に API を呼び出して確定した「権限状態」が表示されます。

### 2.3 API キーの保存場所(安全設計)

- API キーは **OS のキーチェーン**(Windows 資格情報マネージャー / macOS Keychain)にのみ保存されます。設定ファイル `config.json` やローカル DB には保存されません。
- 保存後に API キーを画面上で再表示することはできません。
- プロファイルを変更するとき、API キー欄を空のまま保存すると現在のキーが維持されます。
- 動作ログにも API キーは記録されません(記録されるのは「キーが入力されたか」の真偽値のみです)。

### 2.4 権限による機能差

Backlog 上の権限によって、利用できる機能が変わります。接続テスト時の表示はロール(roleType)による**暫定判定**で、確定した状態は保存後の「権限状態」に表示されます(「接続設定」画面の権限状態は保存直後にだけ表示されます。あとから確認したいときは「ユーザ抽出」画面の上部をご覧ください)。

| 権限状態のメッセージ | 影響 |
|---|---|
| 管理者機能を利用できます(ユーザ一覧・チーム一覧とも取得可能) | ユーザ抽出でスペース全体のユーザ・チームを取得できます |
| 一部の管理者機能が利用不可です(ユーザ一覧の権限がありません。ユーザ取得はプロジェクト単位に縮退します。チーム一覧は取得可能です) | ユーザ抽出が参加プロジェクトの範囲に縮退します |
| 一部の管理者機能が利用不可です(チーム一覧の権限がありません。ユーザ一覧は取得可能です) | 所属チームは参加プロジェクト経由で取得できた分のみ反映されます(取りこぼしがある場合は削除反映を行いません) |
| 管理者機能は利用不可です(ユーザ一覧・チーム一覧とも権限がありません。プロジェクト単位の取得に縮退します) | ユーザ抽出は参加プロジェクトの参加者から合成した情報になります |

課題抽出・一括更新・追加は、一般ユーザ権限でも参加プロジェクトの範囲で利用できます。

### 2.5 プロファイルの切替・削除

- 複数のスペースを登録できます。「接続設定」画面上部の「接続先:」セレクタで切り替えると、その選択は次回起動時にも保持されます。
- 削除は一覧の「削除」ボタンから行います。確認ダイアログで **「ローカルデータ(DB)も削除する(推奨)」** にチェックを入れたまま実行すると、OS キーチェーンの API キーとローカル DB の両方が削除されます。チェックを外すと、取得済みデータ(個人情報を含む可能性があります)がローカルに残ります。
- ローカル DB は「スペースホスト × 接続ユーザ」ごとに 1 ファイルです。そのため **同じスペースに同じユーザで接続している別のプロファイルが残っている場合、DB は共有されているため削除されません**(巻き添え削除の防止)。また、一度も接続テストに成功していないプロファイルには DB が存在しないため、削除対象もありません。

## 3. 画面別ガイド

### 3.1 課題抽出

#### できること

課題を Backlog からローカル DB へ同期し、ローカルに対して検索・絞り込みを行い、結果を Excel へ出力します。

#### 基本手順

1. **プロジェクト** セレクタで対象プロジェクトを選びます。一覧が古い場合は「プロジェクト一覧を同期」を押します(このボタンはプロジェクト一覧を最新化するだけで、課題は同期しません)。
2. **同期** セクションで同期モードを選び、「同期」を押します。
   - **自動(初回はフル同期)**: 同期状態から判定します(未同期・長期間未同期ならフル同期)。通常はこれで問題ありません。
   - **フル同期**: プロジェクトの課題を全件取得し直します。
   - **差分同期**: 前回同期以降の更新のみを取得します。
   - 同期中は「取得中 1,200 / 5,000 件」のように進捗が表示されます。完了すると「取得」「登録・更新」「削除」「所要時間」が表示されます。
3. **検索条件** を指定します。
   - **キーワード**: ローカル DB に保存された**課題キー・件名・詳細**への部分一致です(課題キーを貼り付けて素早く絞り込めます。部分一致のため、たとえば `EXA-1` は `EXA-10` などにも一致します)。スペース(半角・全角)で区切ると複数キーワードになり、「すべて含む(AND)」/「いずれかを含む(OR)」を選べます。入力欄で **Enter** を押しても検索できます。
   - **更新日 / 作成日**: 日付の範囲で絞り込みます。
   - **状態 / 担当者**: 同期済みの課題から作成された候補から選びます。
   - **カスタム属性で絞り込む**: 定義があるプロジェクトでのみ表示されます。型に応じて入力方法が変わります(文字列・文章は部分一致、数値・日付は範囲、単一/複数リスト・チェックボックス・ラジオは選択肢のチェック)。
4. 「検索」を押します。
5. 必要に応じて **Excel 出力** セクションで列を選び、「Excel 出力」を押して保存先を指定します。

#### ヒント・注意

- 検索結果は **200 件ごとのページ表示**です。件数表示は「該当 N 件(x〜y 件目を表示)」となり、結果テーブルの下のページャ(「最初」「前へ」「次へ」「最後」と**ページ番号の入力欄**)で全件を閲覧できます。入力欄は Enter で移動します。範囲外の値は有効な範囲内に補正されます(1 未満は最初のページ、最終ページを超える値は最後のページ)。ページが 1 つに収まる場合、ページャは表示されません。Excel には画面のページに関係なく、条件に一致する**全件**が出力されます。
- ページ表示中に**課題の同期が完了**したり、詳細ポップアップの**「最新の状態を取得」**を実行したりすると、表示中の結果と DB の内容がずれる可能性があるため、「データが更新されました。最新の結果を見るには再検索してください。」と表示され、再検索するまでページ移動はできなくなります。もう一度「検索」を押すと解除されます。
- 検索結果一覧の**課題キーをクリックすると、その課題の詳細がポップアップ表示されます**(状態・種別・優先度・担当者・期限・作成/更新日時・親課題・カスタム属性・詳細本文)。内容は**ローカルへ取り込んだ時点**のもの(通常は最終同期時点)で、表示時に Backlog へ問い合わせは行いません。ポップアップ下部の注記に、その時点の日時が表示されます。ポップアップは「閉じる」・**Esc** キー・背景のクリックで閉じられます。なお**課題の同期中は詳細を開けません**(同期が始まると開いているポップアップは自動的に閉じます)。
- ポップアップの「**最新の状態を取得**」を押すと、**その課題 1 件だけ**を Backlog から取得し直してローカルに反映し、表示と注記の日時を更新します(プロジェクト全体の同期は行われないため、一覧の「最終同期」の表示は変わりません)。反映後は次回の検索から一覧にも新しい値が出ます。
- 課題が Backlog 上で削除されている場合は「削除された可能性があります」というエラーになり、**ローカルの内容はそのまま残ります**(削除の反映はフル同期で行われます)。
- **コメントは同期では取得されません**。「最新の状態を取得」を押した課題についてだけ、その時点のコメントを取得して表示します(ポップアップ最上部に取得状況が表示されます)。まだ押していない課題では「コメントは未取得です」と表示されます。
- コメントは**新しい順**に表示され、件数が多い場合はコメント欄内でスクロールします。状態変更などの**本文が無い変更履歴は件数のみ**(「ほか変更履歴 N 件」)を表示します。
- 1 回の取得で保存するのは**最新 500 件まで**です。これを超える課題では「以前のコメントは Backlog で確認してください」と表示されます。なお、コメントはキーワード検索・Excel 出力の対象外です。
- 課題キーの右隣の**クリップボードのアイコンをクリックすると、その課題の URL がクリップボードにコピーされます**(画面下部中央に「課題 URL をコピーしました(ABC-123)」と数秒間表示されます)。ポップアップ内の「URL をコピー」「ブラウザで開く」からも、URL のコピーやブラウザでの表示ができます。
- 選択できる出力列は、キー・件名・状態・担当者・種別・優先度・作成日時・更新日時・期限・親課題キー、およびカスタム属性です。既定では親課題キーとカスタム属性は選択されていません。
- **列選択でカスタム属性を選ぶと、検索結果の一覧にもその列が表示されます**(反映するには選択後にもう一度検索してください)。
- Excel の出力は「課題」シートと、件数を書いた「情報」シートで構成されます。
- 出力対象が **100 万件** を超える場合は「対象件数が上限(100 万件)を超えています。条件で絞り込んでください」というエラーになり、ファイルは作成されません。
- 検索・Excel 出力はすべてローカル DB に対して行われます。**Backlog 上の最新状態を見るには、先に同期してください。**
- キーワード検索の対象はローカルに保存した課題キー・件名・詳細のみで、コメントや添付ファイルは対象外です。Backlog サイト上のキーワード検索とは範囲が異なります。なお課題キーも部分一致で照合するため、プロジェクトキーだけを入力するとそのプロジェクトの課題すべてに一致します。
- 同期の実行中は、プロジェクト切替・検索・Excel 出力・課題詳細の表示ができません(途中状態のデータを読ませないためです)。

### 3.2 一括更新・追加

#### できること

対象プロジェクトの課題をテンプレート Excel に出力し、Excel 上で編集した内容を Backlog へまとめて反映します。`issueKey` が空の行は新規追加になります。

> **この機能は Backlog のデータを変更します。** はじめてお使いの際は、参加者を自分だけにしたテスト用プロジェクトでの試行を推奨します。

#### 基本手順

1. **① テンプレート出力**: プロジェクトを選び、必要に応じて「出力する課題の条件」(キーワード・更新日・作成日・状態・担当者)を指定してから、「テンプレート出力」を押して保存先を指定します。
   - 条件に**一致した課題だけ**がテンプレートに載ります。**すべて空欄なら対象プロジェクトの全件**が出力されます。
   - 条件は課題抽出画面の検索条件と同じもので、同期済みのローカルデータに対して適用されます(カスタム属性での絞り込みは未対応)。状態・担当者の候補は同期済みの課題から作られるため、未同期のプロジェクトでは選択肢が空になります。
   - 条件を指定してもキーワード欄の Enter では出力しません。出力は必ず「テンプレート出力」ボタンで行います。
   - **重要**: テンプレート出力は最大 100 万件まで出力できますが、**取り込みの上限は 50,000 行**です。出力された行数が 50,000 行を超える場合、そのままでは取り込めません。**条件で絞り込むか、Excel 上で不要な行を削除するか、ファイルを分割してから取り込んでください**(不要な行は行ごと削除して構いません。空欄の行は「変更しない」として扱われますが、行数の上限にはカウントされます)。
2. 出力された Excel を開き、「一括更新」シートを編集します。記入規則は [4. Excel テンプレートの記入規則](#4-excel-テンプレートの記入規則) と、テンプレートの「記入方法」シートを参照してください。
3. **② Excel を取り込む**: 必要に応じて「既定の優先度」(優先度が未入力の新規追加行に適用されます)を選び、「Excel を取り込む」を押して記入済みファイルを選択します。**この操作では Backlog に書き込みません。**
4. **③ 検証結果・変更プレビュー(dry-run)** を確認します。
   - 上部に「取り込み N 行 / 新規追加 N 件 / 更新 N 件 / 変更なし N 件」が表示されます。
   - 検証エラーがあると「検証エラー N 件(修正して取り込み直してください)」と行番号つきで表示され、実行できません。
   - 一覧の「変更内容」列で、行ごとの変更前後が確認できます。
   - 「競合」列が「要確認」の行は、テンプレート出力後にリモートで更新されています。
5. **④ 実行**: 「実行」を押すと確認が表示されます。「N 件を Backlog に書き込みます。よろしいですか?」の内容を確認し、「書き込む」を押します。
   - 実行中は進捗バーと「N / M 件(x%)」が表示されます。
   - 「キャンセル」を押すと中断を要求します。送信中の 1 件を終えてから停止します。
6. **⑤ 実行結果**: 成功・失敗・競合・スキップ・所要時間が表示されます。「結果を Excel 出力」で行ごとの処理結果(完了・失敗・競合・エラー内容)を出力できます。
   - 新規追加が成功した行には、**作成された課題のキー**(`issueKey` 列)と課題 ID(「作成された課題ID」列)が記録されます。ジョブ履歴の「明細を表示」でも「(新規)PROJ-123」のように確認できます。追加した課題を後から探す際にお使いください。
7. **⑥ ジョブ履歴**: 過去の取り込み・実行が一覧表示されます。中断した場合はここから再開します。

#### ヒント・注意

- **1 件ずつ Backlog へ送信します**(バルク API が無いため)。目安は **1,000 件で 8〜10 分** です。画面には対象件数からの所要時間見込みも表示されます。
- **競合検知**: 実行の直前にリモートの更新日時を確認し、テンプレート出力時点(`base_updated`)から変わっていれば**書き込まずに競合として除外**します。上書きしたい場合のみ「競合を上書きして再実行」を使ってください(リモートで行われた変更は失われます)。
- **二重作成防止**: 送信の成否が不明(5xx・応答欠落等)な行は「送信中」のまま保留されます(行明細と結果 Excel では「送信中(結果未確認)」と表示されます)。ジョブ履歴に「送信結果を確認できなかった行があります」と表示され、「送信中の行も再送して再開」を押すと、作成済みの課題と突合したうえで安全に再送します。
- ジョブ履歴の各行では「再開」「競合を上書きして再実行」「明細を表示」「結果を Excel 出力」が使えます。「未処理」「送信中」の件数が残っているジョブが再開の対象です。
- 実行結果の「スキップ」は「取り込み時に変更なしと判定した行」の件数です。キャンセル・中断で処理しなかった行は含まれません。未処理分はジョブ履歴の「未処理」「送信中」で確認してください。
- 完了したジョブの履歴と行明細は **90 日**保持され、その後自動的に削除されます。
- 課題同期の実行中は、プロジェクト切替・テンプレート出力・Excel の取り込み・一括実行ができません(ジョブ履歴の確認と結果の Excel 出力は行えます)。

### 3.3 ユーザ抽出

#### できること

ユーザ一覧と、所属チーム・ロール・参加プロジェクト・管理者プロジェクトを抽出し、Excel へ出力します。

#### 基本手順

1. 画面上部の **権限状態** を確認します(縮退している場合は取得範囲が限られます)。
2. **先にプロジェクト一覧を同期します。**「同期状態」画面(または「課題抽出」画面)の「プロジェクト一覧を同期」を実行してください。
   - ユーザ同期は、参加プロジェクト・管理者プロジェクト・(権限が縮退している場合は)ユーザ集合そのものを **ローカルのプロジェクト一覧から** 組み立てます。
   - **管理者権限があってもこの手順は必要です。** プロジェクトが未同期のままユーザを同期しても**エラーにはならず**、「参加プロジェクト」「管理者プロジェクト」列が空のまま抽出されてしまいます。
3. **同期** セクションの「ユーザを同期」を押します。ユーザ一覧・所属チーム・プロジェクト参加/管理者情報を取得してローカル DB を更新します。
4. **抽出条件** を指定します。
   - **キーワード**: 名前・ユーザ ID・メールアドレスの部分一致。
   - **ロール**: すべて / 管理者 / 一般ユーザ / レポーター / 閲覧者 / ゲストレポーター / ゲスト閲覧者。
5. 「抽出」を押します。
6. **Excel 出力** で列を選び、「Excel 出力」を押します。

#### ヒント・注意

- 画面表示は先頭 **200 件** までです。Excel には条件に一致する全件が出力されます。
- 出力列は ユーザ ID・名前・メールアドレス・ロール・ロール値・所属チーム・参加プロジェクト・管理者プロジェクト です。「ロール値」(roleType の数値)は既定では選択されていません。
- 「ロール」はスペース全体の権限です。プロジェクトごとの権限は「参加プロジェクト」「管理者プロジェクト」列で確認してください。
- **ユーザ一覧の縮退**: 管理者権限が無い場合、スペース全体のユーザ一覧を取得できないため、参加プロジェクトの参加者からユーザ情報を合成します。この場合、プロジェクトが未同期だと「ユーザ一覧(スペース全体)の取得権限がないため、プロジェクトの参加者からユーザ情報を合成する必要があります。プロジェクトを先に同期してください」というエラーで停止します。
- **チーム一覧の縮退**: スペース全体のチーム一覧を取得できない場合は、参加プロジェクトごとのチーム一覧で補います。**「権限が無い場合」と「一時的な通信エラーの場合」で結果が異なります**(いずれも同期結果の「警告」に表示されます)。

  **A. チーム一覧の権限が無い場合(403)** — 権限が縮退したと判断できるため、削除の反映まで行います。

  | 状況 | 結果 |
  |---|---|
  | プロジェクトが未同期 | 補完の対象が確定できないため、既存のチーム情報を**据え置き**ます |
  | 一部プロジェクトのチーム取得に失敗 | 取得できた分のみ反映し、**削除反映は行いません** |
  | 全プロジェクトから取得できた | 取得できたチームで**置き換え**ます(削除も反映) |
  | 全プロジェクトから取得できたが 1 件も無かった | 古い情報を残さないため、チーム情報の**キャッシュを破棄**します |

  **B. 一時的な通信エラー等(権限以外の理由)** — 一時的な障害で情報を失わないよう、**置き換えもキャッシュの破棄も行いません**。

  | 状況 | 結果 |
  |---|---|
  | プロジェクト経由で 1 件でも取得できた | 取得できた分のみ反映し、**削除反映は行いません** |
  | 1 件も取得できなかった | 既存のチーム情報を**据え置き**ます |

- 縮退時に合成したユーザ情報には、メールアドレスなどプロジェクト単位の応答に含まれない項目が空になることがあります。

### 3.4 同期状態

#### できること

データ種別ごとの鮮度(最終同期時刻)を確認し、手動で同期を実行します。レート制限の残量も確認できます。

#### 基本手順

1. **データ種別ごとの最終同期時刻** の表で鮮度を確認します(「最終同期時刻」と「経過」)。同期完了時刻が記録されるのは次の 3 種別です。
   - **プロジェクト**(スペース全体): 「プロジェクト一覧を同期」で更新されます。
   - **課題**(プロジェクトごとに 1 行): 「課題を同期」で更新されます。
   - **ユーザ**(スペース全体): 「ユーザ抽出」画面の「ユーザを同期」で更新されます。チーム・プロジェクト参加ユーザはユーザ同期に含まれますが、個別の行としては表示されません。
2. **手動同期** でプロジェクトと同期モード(自動 / フル同期 / 差分同期)を選び、「課題を同期」を押します。
3. プロジェクト一覧だけを最新化したい場合は「プロジェクト一覧を同期」を押します。

#### ヒント・注意

- **レート制限の残量** は、区分(読み込み / 更新 / 検索 / アイコン)ごとに「残量 / 上限(毎分)」とリセット時刻を表示します。表示は **10 秒ごとに自動更新**されますが、サーバ応答から観測した実測値のため、**表示の更新で API を消費することはありません**。まだその区分の API を使っていない場合は「未取得(API 利用後に表示されます)」と表示されます。
- 課題の同期は「検索」区分、一括更新の書き込みは「更新」区分の枠を使用します。
- 画面下部に動作ログの出力先が表示されます。
- 他の画面で開始した課題同期が実行中の場合は、対象プロジェクト名とともに理由が表示され、プロジェクト切替と同期は実行できません。

### 3.5 アプリ情報

#### できること

バージョン・連絡先・ライセンスと、このパソコンに保存されているデータの場所を確認できます。

#### 表示内容

- **バージョン / 作者 / GitHub / ドキュメント / 連絡先 / ライセンス**: 不具合の報告・要望は GitHub の Issues へお寄せください。「ドキュメント」の「README」「ユーザガイド」は既定のブラウザで開きます。
- **設定フォルダ**: 接続プロファイル(`config.json`)の保存先。
- **ローカル DB**: プロファイルごとのファイルパスとサイズ(WAL・SHM を含む合計)。まだ作成されていない場合は「未作成(接続テスト後に作成されます)」と表示されます。**ローカル DB は削除してもアプリが再取得できます。**
- **動作ログ**: 出力先のパス。不具合の報告時に添付いただくと調査が早くなります。

API キーは上記のいずれのファイルにも保存されず、OS のキーチェーンにのみ保存されます。

## 4. Excel テンプレートの記入規則

この章は「一括更新・追加」で使うテンプレート Excel の記入方法です。

テンプレートの **「記入方法」シート**には主要な規則が記載されています(`#CLEAR#` を使える項目 — 担当者・期限・詳細、親課題キー、カスタム属性 — もシート上の各項目に書かれています)。本章は、シート上に分散している説明を一覧表へ統合したうえで、シートには書かれていない次の点を補足したものです。

- `#CLEAR#` を**使えない**列(件名・種別・状態・優先度、`issueKey`・`base_updated`)
- **新規追加行では `#CLEAR#` をどの列にも使えない**こと
- **新規追加行に状態を指定できない**こと
- ファイルサイズ・データ行数・列数の上限

### 4.1 シート構成

| シート名 | 役割 |
|---|---|
| 一括更新 | 記入対象のデータシート。ここを編集します |
| 記入方法 | 運用ルールと、対象プロジェクトを示す「プロジェクトID」行 |
| マスタ | 種別・状態・優先度・担当者・単一リスト系カスタム属性の選択候補(ドロップダウンの参照先) |

「記入方法」シート先頭の **「プロジェクトID」行は編集・削除しないでください**。取り込み時に画面で選択したプロジェクトと照合し、別プロジェクトのテンプレートを誤って書き込むことを防いでいます。

### 4.2 列の構成

「一括更新」シートの列は次の順に並びます。

`issueKey` / `件名` / `種別ID` / `種別名` / `状態ID` / `状態名` / `優先度ID` / `優先度名` / `担当者ID` / `担当者名` / `期限` / `詳細` / `親課題キー` / `base_updated` / `属性:{定義名}`(カスタム属性、定義順)

**列の追加・削除・並べ替え、ヘッダ名の変更はしないでください。** 不要な行は行ごと削除してください。

### 4.3 基本ルール

| ルール | 内容 |
|---|---|
| 新規追加 | `issueKey` が**空**の行は新規追加として扱います(値がある行は既存課題の更新) |
| 更新の範囲 | **値を入れたセルのみ**更新します(**空欄 = 変更しない**) |
| 値のクリア | 値をクリアする場合は `#CLEAR#` と記入します(空欄はクリアになりません)。使える列は下の表を参照してください。**この機能は実機検証中です** |
| 新規行の必須項目 | **件名**と**種別**(種別名または種別ID のどちらか)が必須です。優先度が未入力の場合は、取り込み時に指定する「既定の優先度」が適用されます |
| 新規行の制限 | 新規追加行に `#CLEAR#` はどの列にも指定できません(クリアすべき既存の値が無いため)。また **新規追加行に状態は指定できません**(状態は追加後の更新で変更してください) |
| `base_updated` | **編集しないでください。** 競合検知(取り込み後にリモートが更新されていないかの確認)に使用します |
| プロジェクト | 行ごとにプロジェクトを変えることはできません |
| 空白の扱い | 取り込み時に各セルの前後の空白は取り除かれます |

**`#CLEAR#` を使える列**

| 列 | `#CLEAR#` | 補足 |
|---|---|---|
| 担当者名 / 担当者ID | 使える | 担当者を未設定にします(担当者ID 列の `#CLEAR#` が効くのは担当者名列が空の行だけです) |
| 期限 | 使える | 期限を未設定にします |
| 詳細 | 使える | 本文を空にします |
| `属性:{定義名}`(カスタム属性) | 使える | その属性の値をクリアします([4.5](#45-カスタム属性)) |
| 親課題キー | 使える | 親子関係を解除します([4.6](#46-親課題キー)) |
| 件名 / 種別 / 状態 / 優先度 | **使えない** | これらは値を空にできない項目です |
| `issueKey` / `base_updated` | **使えない** | 課題の特定と競合検知に使う列です |

> **注記**: 件名・種別・状態・優先度に `#CLEAR#` を指定すると、アプリは「クリアできるのは担当者・期限・詳細のみです」というエラーを表示します。これは固定項目の列だけを対象にしたメッセージで、**カスタム属性列と親課題キー列では `#CLEAR#` を使えます**(それぞれの列で個別に処理されるため、このエラーの対象外です)。メッセージの表現が実際の対応範囲より狭いため、上の表を正としてお読みください。

### 4.4 名前列と ID 列

種別・状態・優先度・担当者には「名前列」と「ID 列」の 2 つがあります。

- 編集は**名前列**から行ってください。名前列のセルを選ぶと「マスタ」シートの候補がドロップダウンで表示されます。
- **名前列に値がある行は、常に名前列が優先されます。** ID 列が名前列と食い違う場合は ID 列を無視し、取り込み結果に警告を表示します。
- **名前列が空の行**は、ID 列の値を使います。
- 担当者名は同名の人を区別するため **「表示名 (ID)」形式**(例: `山田 太郎 (12345)`)で出力されます。ドロップダウンから選べばこの形式になります。

### 4.5 カスタム属性

- カスタム属性は **「属性:定義名」** という列です(固定列の後ろに並びます)。
- 他の列と同じく **空欄 = 変更しない**、`#CLEAR#` = クリア(実機検証中の機能)です。

| 型 | 記入方法 |
|---|---|
| 文字列・文章 | そのまま入力します |
| 数値 | 数値を入力します |
| 日付 | `yyyy-MM-dd` 形式で入力します |
| 単一リスト・ラジオ | 選択肢名をドロップダウンから選びます |
| 複数リスト・チェックボックス | 選択肢名を**カンマ区切り**で入力します(例: `UI, DB`)。読点「、」も区切りとして使えます |

**注意事項**

- 選択肢に無い値(「その他」の直接入力)は**現在未対応**です。
- 選択肢名にカンマ(または読点「、」)を含む複数リスト・チェックボックスは、区切りと区別できないため取り込めません。
- カスタム属性は**課題種別ごとに適用が決まっている**ため、その種別に適用されない属性へ記入するとエラーになります。
- 新規追加行では、その課題種別に適用される**必須のカスタム属性が入力必須**です。
- 文字列として `#CLEAR#` という値そのものを設定する操作は、クリア指示と区別できないため Excel 経由では行えません。

### 4.6 親課題キー

- 親課題を設定・変更する場合は「親課題キー」列に**親課題の課題キー**(例: `ABC-1`)を入力します。
- ローカルに無い課題(未同期)の場合は **`ID:課題ID`** 形式(例: `ID:12345`)でも指定できます。
- **空欄 = 変更しない**、`#CLEAR#` = 親子関係の解除(解除は実機検証中の機能)です。

**制限**

- 親に指定できるのは、既に Backlog に存在する課題だけです(同じファイル内の新規追加行どうしを親子にすることはできません)。
- Backlog の親子は **1 階層まで**のため、(1) 親に指定する課題自身が子課題であってはならない、(2) 親を設定する課題自身が子課題を持っていてはならない、という制限があります。
- 親課題は**対象プロジェクト内**の課題に限ります。
- 課題キーはローカルデータで解決するため、見つからない場合は対象プロジェクトを同期してから取り込み直してください。
- 同じファイルの中で親を解除した課題を、別の行の親として指定することはできません(解除だけを先に取り込み、同期してからテンプレートを出力し直してください)。

### 4.7 記入例

| issueKey | 件名 | 種別名 | 状態名 | 担当者名 | 期限 | 詳細 | 親課題キー | base_updated | 属性:重要度 |
|---|---|---|---|---|---|---|---|---|---|
| ABC-10 | | | 処理済み | | | | | 2026-08-01T09:00:00Z | |
| ABC-11 | 画面の文言を修正 | | | 山田 太郎 (12345) | 2026-09-30 | | ABC-1 | 2026-08-01T09:05:00Z | 高 |
| ABC-12 | | | | `#CLEAR#` | `#CLEAR#` | | | 2026-08-01T09:10:00Z | |
| | 新しい課題を追加 | タスク | | 山田 太郎 (12345) | | 手順を整理する | | | 中 |

- 1 行目: 状態だけを「処理済み」に変更します(他のセルは空欄なので変更されません)。
- 2 行目: 件名・担当者・期限・親課題・カスタム属性を変更します。
- 3 行目: 担当者と期限をクリアします。
- 4 行目: `issueKey` が空なので新規追加です(件名と種別が必須)。

### 4.8 上限

| 項目 | 上限 |
|---|---|
| ファイルサイズ | **100MB** |
| データ行数 | **50,000 行** |
| 列数 | 固定 14 列 + カスタム属性定義数 + 64 列 |

上限を超えると「Excel ファイルが大きすぎます」「データ行が多すぎます(上限は 50,000 行です)」等のエラーになります。ファイルを分けて取り込んでください。

行数の上限は「取り込む行」ではなく **「セルが 1 つでも入っている行」** に対して適用されます。テンプレート出力は最大 100 万件まで行えるため、**課題数が 50,000 件を超えるプロジェクトのテンプレートはそのままでは取り込めません。** テンプレート出力時に条件で絞り込むか、不要な行を削除するか、ファイルを分割してください。なお 1 件ずつ送信するため(1,000 件で 8〜10 分)、実運用では 1 回あたりの件数を数千件程度に抑えることを推奨します。

## 5. データとセキュリティ

### 5.1 保存場所

| データ | 場所 |
|---|---|
| 設定(プロファイル。キーは含まない) | `ユーザ設定ディレクトリ/backlog-assistant/config.json`(Windows: `%AppData%\backlog-assistant\config.json`) |
| API キー | OS キーチェーンのみ(Windows 資格情報マネージャー / macOS Keychain) |
| ローカル DB(取得データ・SQLite) | 同上 `data\<スペースホスト>_<ユーザID>.db`(Unix 系では権限 0600、Windows はユーザディレクトリの ACL に従う) |
| 動作ログ | 実行ファイルと同じフォルダの `logs\`(書込不可の場合はユーザ設定ディレクトリへ自動フォールバック) |

正確なパスは「アプリ情報」画面で確認できます。

### 5.2 同期とローカルキャッシュの考え方

- **検索・絞り込み・Excel 出力はすべてローカル DB に対して行われます。** Backlog へ問い合わせないため高速ですが、**表示される内容は最後に同期した時点の状態**です。
- Backlog へ書き込むのは「一括更新・追加」画面の実行だけです。
- 差分同期は `updatedSince` と activities による削除検知を使い、API 呼び出しを節約します。整合性に不安があるときはフル同期を選んでください。
- 同期の実行中は、途中状態のデータを読ませないため、全画面でプロジェクト切替・検索・Excel 出力・一括更新が抑止されます。

### 5.3 動作ログ

- 実行ファイルと同じフォルダの `logs/` に、`backlog-assistant-YYYYMMDD.log` の形式で日付別に出力されます。
- 平文ログは **14 日**保持されます。それより古いログは起動時にバックグラウンドで gzip 圧縮して `logs/archive/` へ移動し、**アーカイブは 90 日**保持されます。
- **API キー・課題内容・ユーザ名は記録しません。** URL のスペース名やホームフォルダ名はマスクされます。
- 不具合調査時の共有を想定した設計ですが、**共有前に内容をご確認いただくことを推奨します。**

## 6. トラブルシューティング / FAQ

### 接続テストに失敗する

| 症状・メッセージ | 対処 |
|---|---|
| 「認証に失敗しました(API キーが無効です)」 | API キーが正しいか確認してください。コピー時に前後の空白や改行が混入していないか、Backlog 上でキーが削除・無効化されていないかも確認してください(アプリ側でも前後の空白は自動的に取り除きます) |
| 「スペース URL は https:// で始まる必要があります」 | `http://` ではなく `https://` で入力してください |
| 「許可されていないホストです(*.backlog.jp / *.backlog.com のみ利用できます)」 | スペース URL のドメインを確認してください |
| 「スペース URL にパスを含めることはできません」 | `https://example.backlog.jp` のようにホスト名までを入力してください(`/dashboard` 等は不要です) |
| 「権限がありません」 | ユーザ抽出の全件取得には管理者またはプロジェクト管理者権限が必要です。詳しくは [2.4 権限による機能差](#24-権限による機能差) を参照してください |

### 「プロジェクトを先に同期してください」と表示される

管理者権限が無い状態でユーザを同期すると、参加プロジェクトの参加者からユーザ情報を合成します。そのためプロジェクトが未同期だと処理できません。「同期状態」画面(または課題抽出画面)で「プロジェクト一覧を同期」を実行してから、もう一度「ユーザを同期」を押してください。

なお **管理者権限がある場合はこのエラーは出ませんが、プロジェクトが未同期だと「参加プロジェクト」「管理者プロジェクト」列が空になります。** 権限にかかわらず、ユーザ同期の前にプロジェクト一覧を同期してください。

### 「削除の反映を保留しました」という警告が出る

削除候補が **100 件以上**になると、誤削除防止のため削除の反映を保留します。**この保留はフル同期を繰り返しても自動では解除されません。** Backlog 側で実際に大量の課題を削除した場合は、次の手順で解消してください。

1. アプリを終了します。
2. ローカル DB ファイルを削除します(保存先は「アプリ情報」画面に表示されます。同名の `-wal`・`-shm` ファイルも含みます)。
3. アプリを再起動し、フル同期を実行します。

### 「判定できません」というエラーで一括更新ができない

親課題やカスタム属性の現在値をローカルデータから判定できない場合に出ます(旧バージョンで同期したデータ等)。メッセージのとおり **対象プロジェクトをフル同期してから再実行**してください。課題抽出の検索で「N 件はローカルの課題データが古く、カスタム属性の条件を判定できませんでした」と出る場合も、フル同期で解消します。

### 同期中に他の操作ができない

同期の途中でローカル DB を読むと、「取り込み済みのぶんだけ」の不完全な結果が返ってしまいます。それを防ぐため、同期中はプロジェクト切替・検索・Excel 出力・テンプレート出力・取り込み・一括実行を抑止しています。ジョブ履歴の確認と結果 Excel の出力は同期中でも行えます。同期の完了をお待ちください。

### Windows で SmartScreen の警告が出る / macOS で起動できない

配布バイナリはコード署名されていません。

- Windows: 「詳細情報」→「実行」で起動できます。
- macOS: 一度開こうとした後、「システム設定 → プライバシーとセキュリティ」下部の「このまま開く」を選択してください。

必ず公式の [Releases](https://github.com/r404r/p-backlog-assistant/releases) からダウンロードしたものだけをご利用ください。

### アプリが起動しない

起動時に失敗した場合、原因を動作ログに記録します。動作ログも開けない場合は、最後の手段として実行ファイルと同じフォルダ(書き込めない場合はユーザ設定ディレクトリ)の **`crash.txt`** へ追記します。不具合報告の際はこのファイルを添付してください。画面表示中にエラーが起きた場合は「画面の表示中にエラーが発生しました」というメッセージが表示されます。他の画面に切り替えるか、アプリを再起動してください。

### レート制限に引っかかる

Backlog の API にはレート制限があります。本アプリは区分ごとのレート制限を自動で管理し、超過しそうな場合は自動的に待機します(一括更新の書き込みは 1 秒間隔でスロットリングされます)。「同期状態」画面の「レート制限の残量」で、区分ごとの残量とリセット時刻を確認できます。残量が少ない場合は、リセット時刻を過ぎてから再実行してください。

### 課題キーの隣にコピーのアイコンが出ない

スペース URL を解決できない場合、課題 URL を組み立てられないため、クリップボードのアイコン(およびポップアップ内の「URL をコピー」「ブラウザで開く」)は表示されません。「接続設定」画面でプロファイルが正しく選択されているか確認してください(課題キーのクリックによる詳細表示は、この場合でも利用できます)。

### 検索が遅い

- 1〜2 文字のキーワードは全文検索の索引を使えず、全件走査になるため遅くなります。**3 文字以上**のキーワードをお使いください。複数キーワードの場合、AND(すべて含む)なら 3 文字以上の語が 1 つでもあれば索引が使われますが、OR(いずれかを含む)は 2 文字以下の語が 1 つでもあると索引を使いません。
- カスタム属性による絞り込みは、他の条件より時間がかかることがあります。他の条件と組み合わせて対象を絞ってからお試しください。

### 既知の制限

- `#CLEAR#`(担当者・期限・詳細・カスタム属性・親課題のクリア)は公式 API 仕様に明記が無いため、**実機検証中**の機能です。
- カスタム属性の「その他」直接入力(otherValue)の書き込みは**未対応**です。選択肢名にカンマ(または読点「、」)を含む複数選択のカスタム属性も取り込めません。
- 課題の親子関係は **2 階層(親 - 子)のみ**対応です。同一ファイル内の新規追加行どうしを親子にすることはできません。
- キーワード検索は 2 文字以下の語だと索引が効かず遅くなります。
- キーワード検索の対象は課題キー・件名・詳細のみで、コメント・添付ファイルは対象外です。
- 一括更新・追加のテンプレートは、キーワード・更新日・作成日・状態・担当者で絞り込めます(条件を指定しなければ全件)。カスタム属性での絞り込みは未対応です。
